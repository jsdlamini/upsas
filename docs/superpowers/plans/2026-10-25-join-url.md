# Join URL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a public `/join/<slug>` page that scopes student/staff registration to an institution, plus an admin-visible copyable join URL in Settings.

**Architecture:** Self-serve tenants already live in Prisma (`User`, `PasswordCredential`, `RoleAssignment`, `StudentProfile`). Join registration writes directly to Prisma scoped to `tenantId = slug`, so the existing Prisma login path (`findUserPrisma` by email) and session reconstruction (`principalForSessionRecord` → `findUserPrismaById`) resolve joined accounts to the right tenant without touching the in-memory default-tenant store.

**Tech Stack:** Next 15 App Router (server components + server actions), Prisma/Postgres, TypeScript, node:test.

**Spec:** Task brief "Add a shareable join URL" (requirements 1–4, acceptance criteria).

## Global Constraints

- Keep `/register` (default-tenant) flow working unchanged.
- Join endpoint is public; sharing UI is admin-only (existing `config.edit` gate).
- `npm run typecheck`, `npm test`, `npm run build` must pass.

## Review Focus

- Unknown/suspended slug must not accept registrations and must show a clear "not found" message.
- Duplicate email or student number must return a friendly error, not a 500.
- A joined student must resolve to their institution's tenant on sign-in.
- The join URL must remain visible to a signed-in admin at any time (Settings page).
- A tenant slug that collides with the `/join` route must not shadow it (reserve `join`).
